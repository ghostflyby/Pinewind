# Pinewind 包管理与配置组合设计

本文面向维护或扩展 Pinewind 的开发者,规定配置语义、来源身份、组合不变式与接口边界。使用方式见 [README](../README.md),贡献流程见 [CONTRIBUTING](../CONTRIBUTING.md)。

“预设计”章节描述尚未提供的编排与同步能力,不代表现有 API 已实现。其余章节说明现有模型与行为。

## 1. 职责与目录模型

Pinewind 提供 `PinewindCore` Swift 库,不依赖输入法引擎。调用方负责目录位置、认证、引擎部署及 UI;库负责解析配置、准备来源和生成组合目录。

| 目录角色 | 内容 | 所有权 |
|---|---|---|
| 输入域 | 用户文件、manifest、本地覆写与共享锁 | 用户编辑;库通过显式 API 写锁 |
| 缓存域 | Git 对象、commit 源码快照及可抛弃的准备数据 | 库管理,不进入用户仓库 |
| 组合域 | 用户文件与包内容按声明次序生成的结果 | 库生成,调用方只读消费 |

三个根目录由调用方传入。机器路径、认证及后端选择不属于用户 manifest,库不修改用户的 `.gitignore`。

核心不变式:

- 取包、conf 求值和组合不回写输入文件。
- 组合结果以净态按声明顺序执行为基准;失败保留上一份完整输出。
- 用户文件可以保留任意子目录,其相对路径就是输出路径。
- 远程源码的版本由完整 commit 固定,独立下载资源由内容校验值固定。
- 缓存可删除。重建仍要求来源能提供锁定版本,不承诺远端永久保留旧内容。
- 本地工作树是实时输入;启用本地覆写后,共享锁不能单独复现本机编辑结果。

## 2. 用户配置

### 2.1 文件职责与编码

| 文件 | 写入方 | 是否随用户仓库同步 |
|---|---|---|
| `pinewind.yaml` | 用户 | 是 |
| `pinewind.local.yaml` | 用户,可选 | 否 |
| `pinewind.lock` | 库 API | 建议同步 |

manifest 和本地覆写使用 UTF-8 YAML,顶层整数 `version: 1` 必填。缺失版本、不支持的版本、重复键、未知字段和错误类型均报错。URL、ref、commit、recipe 与 option 值使用字符串;易被 YAML 推断成数字或布尔值的内容需要加引号。

锁是库管理的不透明文件,不承诺字段布局、文本或二进制编码。plum conf 和 recipe 使用各自的生态格式,不要求添加这个 version 字段。

### 2.2 Manifest

```yaml
version: 1
names:
  emoji:
    url: https://github.com/rime/rime-emoji
    ref: master
order:
  - self
  - name: emoji
    recipe: customize
    options:
      schema: luna_pinyin
  - import: ":preset"
```

`names` 可省略,缺省为空映射。短名定义不安装包,只有 `order` 中的引用才应用。`order` 是有序序列,保留重复条目;每个条目只能有一种主选择器:

| 选择器 | 写法 | 可选字段 |
|---|---|---|
| 用户文件 | `self`,或 `self: {include: [...], exclude: [...]}` | include / exclude 位于 self 映射内 |
| 短名 | 标量短名,或 `name: <短名>` | ref / commit / recipe / options / include / exclude |
| 直连包 | `url: <URL>` | ref / commit / recipe / options / include / exclude |
| conf 导入 | `import: <内置名、本地相对路径或 HTTPS URL>` | variables |

- `self` 是保留名。存在 manifest 时不隐式插入 self;它可出现零次或多次。没有 manifest 时才等价于 `[self]`。
- `ref` 表示分支或 tag 请求;缺省表示仓库默认分支。`commit` 是完整的 40 位十六进制 commit,与 ref 互斥。已锁版本与显式 commit 必须一致。
- `recipe` 缺省按包内文件选择;`options` 是字符串映射,缺省为空,不是 shell 代码。
- import 在当前位置按序展开,不合并相同 URL 的不同应用。HTTPS conf 选择器可以解析,其远程资源获取仍需调用方准备。

### 2.3 短名与本地覆写

```yaml
version: 1
names:
  emoji:
    url: file:///path/to/rime-emoji
```

合并次序是 manifest.names → 本地 names → 条目内联字段,后层胜。合并以字段为单位:未出现的字段继承,出现的字段整体替换;options 不逐键合并。可选字段的 `null` 清除继承值,回到该字段缺省。最终包条目必须有有效的绝对 URL。

`file://` 表示本机文件树,不要求 Git 仓库,不读取 HEAD,不 hash 目录或生成本地锁。覆写层改向 file URL 时,清除该层未指定的继承 ref/commit;显式为本地 URL 指定 ref/commit 是错误。

共享声明与本地覆写应分别加载:用 `Manifest.load(applyLocalOverrides: false)` 得到共享声明并验证锁,再用本地覆写形成执行声明。`Resolution` 不持久化本地源码条目。本地覆写不改写共享锁。

### 2.4 文件过滤与 glob

候选文件集来自用户树、默认白名单或 recipe。include 缺省允许完整候选集,exclude 缺省为空。先与 include 匹配集取交集,再排除 exclude;include 不扩大候选集。过滤同样应用于补丁目标。

匹配使用根相对路径,区分大小写:`*`、`?` 和字符类不跨 `/`,`**` 可跨目录,中间的 `**/` 可匹配零层目录。通配符可匹配点文件;不启用 extglob、brace expansion 或反斜杠转义。绝对路径、父目录段、反斜杠与 NUL 被拒绝,非法模式给出诊断。匹配顺序不依赖宿主 shell、locale 或目录枚举顺序。

## 3. 来源身份与取包

### 3.1 身份与传输地址

源码身份是规范化 URL + commit,与 recipe、options、过滤规则及条目位置分开。同一源码版本可复用快照,不同应用仍分别参与组合。

HTTPS URL 规范化包括协议和主机名小写、去默认 443 端口、尾斜杠和 `.git` 后缀;GitHub owner/repo 路径同时转小写。URL 不携带凭证、查询或 fragment。file URL 只能指向本机绝对路径。

传输地址与身份分开处理:GitHub 地址验证 owner/repo 并补 `.git`;非 GitHub 请求及锁记录保留调用方的 `.git` 后缀,按该地址访问远端。带/不带后缀的身份可共用缓存,Rx 与跨包寻址使用规范化身份。

### 3.2 HTTPS Git 后端

`PackageFetcher` 分开提供默认分支解析、ref 到 commit 的解析、源码快照准备和独立文件下载。`GitKitPackageFetcher` 使用 GitKit 的 libgit2 C 接口执行进程内 HTTPS Git 操作,不调用外部 git/ssh 命令。

- refs 广播提供 HEAD、分支和 tag OID。附注 tag 使用 peeled OID。短名同时匹配分支和 tag 时诊断歧义,调用方可指定 `refs/heads/...` 或 `refs/tags/...`。
- 完整 commit 不需要联网解析,准备源码时检查对象是否存在。
- 对象缓存 fetch 普通分支与 tag 的历史,复用已有对象。锁定 commit 不在其中时尝试按 OID 获取;不可用或服务器拒绝时失败,不回退分支头。
- 从精确 commit 的 tree 导出源码,关闭工作树过滤器,保留原始 blob 字节。候选快照完整后才发布,成功导出的 commit 保留私有引用。
- 下载检查 HTTP 状态,拒绝降级到 HTTP 的重定向。凭证由同步回调提供,不写入源码 URL 或共享锁。

所有后端实例共享阻塞 I/O 的串行执行器,Git 操作及源码缓存发布在本进程内串行。独立文件下载等待 URLSession 时可并发。跨进程缓存协调尚未提供。

首次获取不是浅克隆,不承诺最小传输量。子模块不递归获取,gitlink 至多留下空目录;LFS pointer 按普通 blob 导出,不自动获取 LFS 对象。源码快照拒绝符号链接。

### 3.3 缓存与资源准备

缓存保存可复用的对象仓库和不可变 commit 快照。URL 元数据的 SHA-256 仅用于生成私有缓存路径键,不 hash 源码树或 commit 归档。完成记录与目录共同判断快照是否可复用;不完整候选可丢弃。缓存布局与记录编码属于实现细节。

`download_files` 不受仓库 commit 约束,每项资源需要 URL、目标相对路径和实际字节 SHA-256。组合前必须准备相应 `PinnedResource` 并核对内容;校验失败不接受新内容或自动改锁。

独立资源覆盖在条目专属准备视图中进行,不修改共享源码快照。后端下载 API 只返回字节,资源锁生成及准备视图的自动编排尚未提供。

## 4. plum conf 导入

兼容边界是包描述符、conf 的求值语义和 recipe 数据。plum 的本机缓存布局与就地修改用户目录行为不属于 Pinewind 的接口。

### 4.1 包描述符

```text
<owner>/<repository>@<ref>:<recipe>:key=value,...
```

owner 缺省为 `rime`;裸名 `foo` 展开为 `rime/rime-foo`,已带 `rime-` 前缀时不重复添加。ref、recipe 和 options 可省略;空 owner/repo/ref 段及重复 option 键报错。options 作为字面字符串翻译为 `PackageRequest`,不经 shell eval。

`:preset`、`:extra`、`:all` 展开为有序内置列表。本地 conf 使用输入域相对路径。原生短名表与 plum 裸名展开互不替代。

### 4.2 沙盒求值

`PlumImporter` 使用 SwiftBash 的 `BashInterpreter` 求值,完成后读取索引数组 `package_list`,再翻译描述符。数组初始化、重置、追加、引号、参数展开、控制流和重复 source 均采用解释器语义。

每个原生 import 使用独立环境。变量仅由 `variables` 显式提供;库保留 `root_dir`,不继承宿主环境。include 资源位于只读挂载域,不允许写宿主输入、符号链接逃逸、宿主进程执行或网络访问。权限边界由挂载和命令能力控制,不另设 bash 语法子集。

默认求值超时为 5 秒,可由调用方配置。一次求值最多读取 64 次 source、单文件 1 MiB、累计 4 MiB;重复读取计入预算。失败、超时或取消中止导入,不保留部分展开结果。

远程 conf 自动获取尚未提供。调用方可准备完整的只读资源视图,使用 `evaluate(file:resourceRoot:variables:)`;解释器本身不负责联网下载 include。

## 5. Recipe 与补丁

### 5.1 文件选择

选择顺序是显式 `<recipe>.recipe.yaml` → 包内默认 `recipe.yaml` → 默认白名单。显式选择的 recipe 必须存在,其 `recipe.Rx` 必须与选择名一致。

默认白名单只包含顶层 `.yaml`、`.txt`、`.gram` 与单层 `opencc/` 中的 `.json`、`.ocd`、`.ocd2`、`.txt`;排除 `.custom.yaml`、`.recipe.yaml` 和 `recipe.yaml`。其他子目录不递归选取。

`install_files` 使用 glob 列表,也接受按行或折叠字符串表达的模式。显式模式没有匹配文件时给出诊断。`../<包>/<pattern>` 在已准备的来源间寻址,不作为输出路径:来源需位于同一规范化 URL 父路径,包名剥 `rime-` 前缀。同一 URL + commit 的重复准备不制造歧义;缺失或同时匹配多个版本时报错,不自动取回未准备的包。

`download_files` 接受 HTTPS URL 或 `<filename>::<url>`;目标必须是安全的相对路径,同一 recipe 内不得重复。其资源版本与准备规则见第 3 节。

### 5.2 Option 替换

options 必须在 `recipe.args` 中声明。补丁目标和补丁体支持 `$name`、`${name}` 和 `${name:-default}`,替换值不再次解析为 shell 代码。

无缺省的变量接受显式空串;缺值时报错。`:-` 对缺失或空值采用缺省。未声明变量时报错。展开后的目标仍须通过相对路径校验。

补丁体以 YAML 序列表示,经解析、语义等价重序列化和 option 替换后使用,不承诺原始缩进、引号或折叠样式的逐字保真。

### 5.3 应用次序与 Rx

每个包条目先安装文件,立即应用其补丁,再进入下一条目。补丁基底是该时刻组合结果中的同名文件,可来自当前包、self 或先前条目。

- 目标缺失时创建父目录与 `__patch` 段;目标存在但没有该段时补建。
- Rx 标记采用 `<owner>/<repo>:<recipe>:<options>` 形态,由规范化 URL 与有效参数推导。
- 同一目标内同一 Rx 的旧块全部删除,本次块在段末追加;不同 Rx 按应用次序保留。旧块也可能来自 self 或拷入的包文件。
- 后续整文件写入可覆盖此前所有补丁,不在最后重新补回。self 放最后时,其同名文件决定结果。
- 未被替换的块及注释保留原文;输入文件不被回写。

例如 `[A, self, B]`:A 安装并补丁 → self 覆盖同名文件 → B 安装并补丁。B 只提供补丁时作用于 self 的基底;B 安装同名文件时先覆盖基底。

现有 `__patch` 需为块式 YAML 序列;其他形式的保真转换尚未支持。

## 6. 规划、执行与发布

`CompositionPlanner` 为每个目标保留完整有序操作链,包括已被后续写入覆盖的来源,以支持删除条目、重排和来源回退。计划记录来源与操作,不驻留全部文件字节。

规划时将首次引用的文件与 recipe 捕获到计划持有的磁盘快照,同一来源只捕获一次。原地编辑在下次规划生效;规划期间并发编辑整个输入树仍需调用方协调。快照根可由调用方注入,不得与输入来源重叠,最后一个计划所有者释放后清理。快照不通过硬链接共享可变输入。

`Composer` 按输出文件执行操作链,普通文件复制和比较按文件或分块处理;补丁仍可能占用单个目标的字节与 YAML 解析内存。未变化结果返回原输出,有变化时生成完整候选代次后原子发布,并报告变化、删除与复用路径。

输入、输出及快照根不得违规重叠。self 排除 `.git/`、`.DS_Store`、`*.local.*`、manifest、本地覆写和锁等库元数据。源码视图不接受符号链接。

同一输出根应交给同一个 Composer actor。跨 Composer 实例或进程的输出协调尚未提供。跨平台发布实现须保持完整代次切换语义,不能用逐文件覆盖活跃目录替代。

## 7. 锁与现有接口边界

`Resolution` 保存共享声明、完整有序展开结果和 `LockedPackage`;每个锁定包带源码请求、commit 与独立资源版本。相同 URL 的多次应用不能合并为一条声明。

锁不保存本机路径、认证、部署账本、执行缓存或取包时间。声明匹配比较经过配置解析的字段,不计算声明或目录树哈希。显式 commit 与锁不一致时报错。

库提供锁的读取、验证与原子写入 API,不承诺内部序列化结构。不支持或损坏的锁给出诊断,不静默重新解析为新版本。

现有接口分工:

| 接口 | 职责 |
|---|---|
| `Manifest.parse/load` | 配置解析、短名合并与本地覆写 |
| `PlumImporter.expand/evaluate` | 内置列表与已准备 conf 的有序展开 |
| `PackageFetcher` / `GitKitPackageFetcher` | 引用解析、源码快照准备、独立 HTTPS 下载 |
| `PreparedPackage` | 调用方交给组合层的来源与资源视图 |
| `CompositionPlanner.plan` | 选择文件并形成快照绑定的操作计划 |
| `Composer.compose` | 生成、发布结果并返回变更报告 |
| `Resolution` / `LockedPackage` | 解析结果、声明匹配与锁读写 |

planner 不自动取包、读取共享锁或生成资源版本;调用方需先展开 import,准备远端包与独立资源并验证锁。自动 resolve/update 编排、远程 conf 资源视图、目标 sync 和 CLI 尚未提供。

## 8. 解析与更新编排(预设计)

resolve 保留仍匹配声明的锁定版本,只解析新增或改变的声明;update 重解析指定范围的浮动 ref、conf 与独立资源,显式 commit 不前进。fetch 按锁准备来源,compose 消费已准备输入,sync 只部署结果;后三者不修改共享锁。

同一源码 ref 在一次解析事务中只解析一次,避免分支在请求间移动。完整解析、下载与校验成功后才发布新锁。共享声明与锁不匹配时要求显式 resolve,不通过 compose 自动联网或改锁。

远程 conf 的锁定结果应覆盖其显式变量、完整展开顺序及 include 资源的 SHA-256。锁内展开固定后,compose 不重新下载可变清单检查变化。

独立资源首次解析建立校验值,后续 resolve 保留仍匹配的记录。相同 URL 返回新内容不自动刷新版本;fetch 校验失败中止,只有 update 可接受新版本。资源在锁定字节已不可取回且无缓存时报告失败。

本地覆写在共享锁验证后应用。保留远端来源及版本请求时沿用锁定 commit;改为其他远端时使用显式 commit,或为本次开发执行解析浮动 ref。会话解析结果可留在可抛弃私有缓存中,不生成本地锁。开发 recipe 改变资源声明时需为本次计划重新准备并校验资源,不改共享锁。

## 9. 目标同步与恢复(预设计)

每个本机目标保存独立的私有受管文件账本,状态绑定目标位置,不同机器或目标不能互作删除依据。只管理文件,不拥有整个目录。删除集合是上次成功文件集减去本次文件集;仅清理删除后为空的目录。

未受管文件默认不修改。新结果与未受管文件同路径时报告冲突,显式接管由调用方授权。userdb、build、installation.yaml、user.yaml 等引擎运行状态始终受保护。账本不进入共享锁,compose 不修改部署状态。

写目标前预检冲突、准备事务专属的不可变文件视图并持久化恢复计划;旧账本继续表示上次成功状态。同目标操作互斥,中断后依原计划向前恢复,未恢复前不启动新同步。全部文件操作成功后原子提交新账本,再清理事务视图。恢复视图缺失时报告状态损坏,不继续删除目标;不承诺自动回滚目录。

## 10. 增量执行(预设计)

### 10.1 正确性基准与来源链

同一声明、锁与源快照下,增量结果须与全量结果一致,包括文件集、删除、覆盖、Rx 替换及诊断语义。缓存缺失、失效依据不足或语义版本不兼容时退回全量执行。

每个输出保留完整来源与有序操作链。例如 A 写 x.yaml,B 覆盖:移除 B 后应恢复 A,不能只删旧输出。补丁修改或撤销从相应基底重放,不从已合并文件反向恢复。

结果内容可以从新计划中最后一次整文件写入开始重放后续补丁;被覆盖贡献的必要校验不能因此略去。新增、删除或重排条目时重新确定获胜写入与补丁链;没有文件基底时使用补丁目标创建语义。

### 10.2 依赖与失效

| 变化 | 需要重查的范围 |
|---|---|
| URL、commit、资源版本 | 对应准备视图及读取它的操作 |
| recipe、options、过滤规则 | 文件选择、目标路径及补丁;包含旧路径退出与新路径进入 |
| 条目新增、删除、重排 | 获胜来源、补丁顺序及跨包消费者 |
| 本地文件修改 | 读取该文件的操作及其目标 |
| 文件新增、删除、改名 | 目录/glob 匹配集及来源回退 |
| 跨包来源变化 | 所有读取该来源的条目 |
| 执行语义版本变化 | 用旧语义生成的私有缓存 |

glob 同时依赖模式、搜索范围与目录成员,不能只记录上次匹配文件。跨包操作绑定实际读取的源码版本,不能只看消费者自己的 commit。

本地变更通知、文件元数据和调用方变化集仅作优化提示;漏事件或证据不足时重新枚举、比较字节或重算,不以目录树哈希代替这些语义。复用中间结果还需比较参数、补丁基底与执行语义版本。

### 10.3 缓存与发布

增量来源依赖、变化记录及中间结果是可抛弃私有状态,不进入锁。它们与不可变源码快照分开管理;存储布局不属于用户配置协议。

复用的文件在修改前必须成为独立可写副本,不能通过硬链接修改已发布结果。完整候选验证成功后才发布文件集和内容,同步账本仍只在同步成功后提交。

当前实现复用取包对象、完整源码缓存与未变化输出,仍按全量组合语义执行操作链;不承诺最小重算集合或持久化增量依赖缓存。
